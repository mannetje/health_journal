# C4 architecture diagrams

This page describes Health Journal with the [C4 model](https://c4model.com/): four zoom levels, from the system in its surroundings down to the components inside a module. The diagrams are Mermaid, so they render on GitHub and live next to the code. For the reasoning behind the shape see [ADR 0002](../adr/0002-hexagonal-architecture.md); for a code-level tour see [Architecture](architecture.md).

| Level | Question it answers | Section |
|---|---|---|
| 1. System context | Who uses the app and what does it touch? | [Context](#level-1-system-context) |
| 2. Containers | What are the deployable and buildable parts? | [Containers](#level-2-containers) |
| 3. Components | What is inside each module? | [Components](#level-3-components) |
| Dynamic | How do the parts talk during one scenario? | [Scenarios](#dynamic-views) |

## Level 1: System context

There is no server. The person using the app, the Android system and a file are the only things around it. Nothing leaves the device unless the user exports a CSV file themselves.

```mermaid
C4Context
    title System context: Health Journal

    Person(user, "Person logging their health", "Records weight, blood pressure, glucose, waist, activity and medication")
    System(app, "Health Journal", "Offline-first Android app. A personal log, not a medical device")
    System_Ext(android, "Android", "Notifications, alarms, file picker, language and region")
    System_Ext(csv, "CSV file", "Export and import of all data, also the Libra weight format")
    System_Ext(sources, "Reference websites", "apotheek.nl, Thuisarts, NHG. Opened in the browser, never called by the app")

    Rel(user, app, "Logs entries, reads history, trends and adherence")
    Rel(app, android, "Posts reminders, sets one alarm, picks files")
    Rel(user, csv, "Chooses where the file is saved or read from")
    Rel(app, csv, "Writes and reads (UTF-8, metric units)")
    Rel(user, sources, "Follows links from the notice and range labels")
```

What the context excludes on purpose: no account, no cloud, no analytics, no `INTERNET` permission, no logging ([privacy spec](../../openspec/specs/privacy/spec.md)).

## Level 2: Containers

In C4 a container is a separately buildable or runnable unit. Here the three Gradle modules are the containers, plus the SQLite file they share at runtime.

```mermaid
C4Container
    title Containers: Gradle modules and the local database

    Person(user, "User")

    System_Boundary(sys, "Health Journal (one Android APK)") {
        Container(app, "app", "Android application, Kotlin, Jetpack Compose", "Screens, ViewModels, preferences, reminder alarm and notifications. Composition root")
        Container(domain, "domain", "Pure Kotlin JVM library", "Model, rules, use cases and the ports. No Android, no Room")
        Container(data, "data", "Android library, Room, CSV", "Adapters that implement the domain ports")
        ContainerDb(db, "health_journal.db", "SQLite via Room, schema v6", "Profiles, metrics, medication, schedule versions, intakes")
    }

    System_Ext(android, "Android", "AlarmManager, NotificationManager, file picker")
    System_Ext(csv, "CSV file")

    Rel(user, app, "Uses")
    Rel(app, domain, "Calls use cases, uses model")
    Rel(data, domain, "Implements ports")
    Rel(app, data, "Builds DataModule once (HealthJournalApp)")
    Rel(data, db, "Reads and writes")
    Rel(data, csv, "Exports and imports")
    Rel(app, android, "Alarm, notification, file picker")
```

Dependency rule: `app` and `data` point at `domain`; `domain` points at nothing. `app` reaches `data` in exactly one place, `HealthJournalApp`, which wires the adapters to the ports.

## Dynamic views

### Recording a blood pressure reading

```mermaid
sequenceDiagram
    actor U as User
    participant S as LoggingScreen
    participant VM as LoggingViewModel
    participant UC as RecordBloodPressureUseCase
    participant P as HealthLogRepositoryPort
    participant R as RoomHealthLogRepository
    U->>S: Save
    S->>VM: saveCurrentMetric()
    VM->>UC: invoke(profileId, reading)
    UC->>UC: BloodPressureReading validates ranges
    UC->>P: saveBloodPressure(entry)
    P->>R: implemented by the Room adapter
    R->>R: map to entity, insert
    R-->>VM: success
    VM-->>S: UiState with UiText message
```

The full walk-through with code is in [Life of an entry](life-of-an-entry.md).

### A reminder fires and the user taps Taken all

```mermaid
sequenceDiagram
    participant AM as AlarmManager
    participant RR as ReminderReceiver
    participant C as ReminderCoordinator
    participant U as RearmRemindersUseCase
    participant N as ReminderNotifier
    actor User
    participant AR as ReminderActionReceiver
    participant T as TakeAllForSlotUseCase
    participant DB as MedicationRepositoryPort

    AM->>RR: alarm for slot 08:00
    RR->>C: onAlarm(slot)
    C->>T: slotAt(profile, slot)
    T->>DB: planned and recorded intakes
    C->>N: post notification (only if something is open)
    C->>U: rearm
    U->>AM: set alarm for next slot (NextSlot)
    User->>AR: Taken all (does not open the app)
    AR->>C: takeAll(slot)
    C->>T: invoke(profile, slot)
    T->>DB: save intakes (Taken)
    C->>N: cancel notification
```

One alarm exists at any time. After a restart, an update, a clock or time-zone change the `RescheduleReceiver` calls `rearm()`. See [ADR 0022](../adr/0022-medication-reminders.md).

### Opening the adherence view

```mermaid
sequenceDiagram
    actor U as User
    participant V as AdherenceView
    participant VM as MedicationViewModel
```

## Deployment

```mermaid
flowchart TB
    subgraph dev["Developer machine / GitHub Actions"]
        SRC["Source<br/>domain, data, app"]
        KS[("app/debug.keystore<br/>fixed key, ADR 0008")]
        GR["Gradle<br/>tests, lint, assembleDebug"]
        SRC --> GR
        KS --> GR
    end
    GR --> APK["health-journal-vX.Y.Z-debug.apk"]
    APK --> REL["GitHub Release<br/>(tag vX.Y.Z)"]
    REL -->|"sideload"| PHONE
    subgraph PHONE["Android device"]
        INST["Health Journal process"]
        FS[("App-private storage<br/>health_journal.db, preferences")]
        SYS["AlarmManager<br/>NotificationManager"]
        INST --> FS
        INST --> SYS
    end
```

| Concern | Decision |
|---|---|
| Distribution | debug-signed APK on GitHub Releases, same key every time so updates install in place |
| Network | none: no `INTERNET` permission |
| Permissions | `POST_NOTIFICATIONS`, `SCHEDULE_EXACT_ALARM` (optional, falls back to inexact), `RECEIVE_BOOT_COMPLETED` |
| Storage | one private SQLite database and `SharedPreferences`; the database is not encrypted yet (proposed in `add-database-encryption-and-lock`) |
| Entry points | `MainActivity`, `ReminderReceiver`, `ReminderActionReceiver` (not exported), `RescheduleReceiver` (system broadcasts only) |

## Keeping these diagrams true

- A new port, module or receiver changes level 2 or 3: update the matching diagram in the same change.
- Mermaid C4 is still marked experimental. If GitHub stops rendering a `C4*` block, switch that block to a `flowchart` with subgraphs; the content stays the same.
- Names in the diagrams are the real class and package names, so a search finds them.
